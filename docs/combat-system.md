# 战斗体系开发说明

本说明对应 v0.0.46。重构保留现有基础战斗与成长节奏；新增专属强化会改变选取后的数值。世界探索、地形、角色外观与存储方式沿用现有机制。

## 分类与唯一状态

| 概念 | 状态所有者 | 规则 |
|---|---|---|
| 角色等级 | `Game.player.level` | 击杀经验自动升级；没有攻击等级或等级解锁槽位 |
| 角色属性强化 | `CombatBuild.attributes` | 攻击、生命、移动、恢复、拾取等；强化次数不是角色等级 |
| 武器 | `CombatBuild.weapons` | 飞矢、环刃；拥有基础等级、强化、分支、形态、装备状态 |
| 技能 | `CombatBuild.skills` | 大地回响、唤雷、手动天雷及六种自动超级技能 |
| 路线与进化 | 同一武器或技能记录 | 路线本身无等级；进化改变形态，保留原有投入 |
| 灵晶强化进度 | `CombatBuild.progressionTier` | 从 1 开始表示下一次选择档位；已购买次数为档位减 1 |

`category` 区分属性、武器、技能；`activation` 区分自动与手动；`tier` 区分常规与超级；`binding` 留出角色绑定与武器绑定语义。这些维度互不替代。目前未新增额外武器绑定技能、武器库存商店或武器掉落。

武器和技能的显示等级由基础等级、专属强化次数及飞矢付费路线选择合计。基础等级仍决定原技能形态与数量；强化次数不能绕过基础数量上限。环刃、地震和唤雷基础最高 5 级，天雷及六种首领技能最高 3 级。分支与进化后的专属强化有各自上限。

旧 `Game.levels/branches/evolutions/skillLevel/rescuePower` 与 `SuperSkills.owned` 是实时兼容视图，不能再维护第二份独立数据。`Game.weapons/skills` 是刷新生成的展示集合，不是可写成长源。

## 模块职责

| 模块 | 责任 |
|---|---|
| `combat-catalog.js` | 能力和升级定义、归属、前置条件、上限与每次强化效果 |
| `combat-build.js` | 唯一成长状态、装备状态、合法升级、分支选择、快照与预览 |
| `combat-stats.js` | 根据角色、构筑、临时增益计算攻击、生命、移动和各能力数值 |
| `combat-progression.js` | 稳定三选一、卡池分组、重新校验、扣费、即时治疗与进度推进 |
| `combat-attacks.js` | 飞矢、环刃、地震、唤雷和手动天雷的施放、投射物和计时 |
| `combat-resolution.js` | 目标资格、攻击上下文、命中、受伤、死亡及世界奖励钩子 |
| `combat-status.js` | 流血、感电、传导和消耗联动；次级伤害不递归触发 |
| `super-skills.js` | 六种自动超级技能的执行、独立冷却与首领奖励事务 |
| `upgrade-presentation.js` | 克隆构筑进行升级预览，不改变当前状态或抽取新选项 |
| `engine.js` | 游戏循环、世界编排与原有调用入口的委托 |

## 数值和伤害约定

角色参考攻击为 32。角色攻击 = 32 ×（1 + 攻击属性加成 + 援助之力加成 + 角色等级加成）。单次伤害 = 能力基础伤害 × 自身强化倍率 × 角色攻击 / 32 × 外部临时倍率。每个能力先由自身数值解析器处理专属强化，再统一套用角色和外部加成；不能再次乘 `stats.damage`。

基础生命保存为 `player.baseMaxHp`，最大生命由基础、角色等级和目录中的生命强化共同派生；购买生命强化只执行目录定义的即时治疗。角色级别增加生命后恢复同样的 2 点，不重复增加基础生命。防御当前默认 0，保留减伤接口，没有新增防御卡。

`combat.createAttack({source, actor, origin, baseDamage, weaponId, skillId})` 对主角来源缩放一次。若传入 `damage`，含义是已经结算好的伤害快照，不再缩放。施放者归属随攻击上下文进入状态结算，非主角施放同一技能也不会继承主角攻击。

投射物、地震回波和持续超级技能保存施放时的伤害；施放后获得强化或狂暴结束不会重算已发出的攻击。伙伴和天使使用自己的攻击数值。流血与感电同样保存伤害，不叠层、不递归触发。

`combat.canTarget()` 是纯查询，可组合可见范围、距离、飞行目标和城堡墙体条件，不揭开迷雾、不唤醒守卫。合法命中才触发首领及城堡守卫激活；盾吸收伤害仍能唤醒合法目标。未来高度规则应接入此目标/路径判定接口，本次未实现高度层。

## 成长和装备事务

灵晶仍是混合三选一，优先按新能力、已有能力强化、属性分配机会，再在组内抽取，避免扩充技能后淹没属性或新能力。首次选择保持环刃、大地回响、唤雷。分支同时展示两个互斥选项和一个延期选项；成功购买才推进路线轮询。

同一面板缓存不可变选项。购买时再次验证资源、拥有状态、上限和路线前置条件，成功后扣费、增加档位、更新形态和派生数值，再检查剩余灵晶。不能以过期卡片绕过要求。Boss 首次解锁独立于灵晶池，获得后才可进入普通强化候选。

暂停构筑面板允许启停已拥有武器，至少保留一件；待领奖、升级或交易时禁用操作。停用保留等级、路线与强化，不重置冷却，并移除对应在途飞矢和环刃。已经施加于敌人的短期状态正常结束。独立技能和另一件武器不受影响。

`serialize()` / `CombatBuild.fromSnapshot()` 是版本化构筑快照，校验等级、上限、路线、形态和强化前置条件。它不包含世界、位置、生命和计时，不能当作完整存档；本次没有新增跨对局存档。

## 后续扩展

新增能力时，先声明目录元数据及稳定 ID，再增加记录和数值解析、施放执行与表现；攻击统一进入公共结算，避免复制击杀与奖励逻辑。新增强化时在目录声明归属、前置条件、上限及效果，由派生数值消费同一效果，卡片通过克隆构筑展示变化。不要增加专门的第二份等级对象。

验证入口为 `npm run check` 与 `npm test`。新增战斗体系回归覆盖基础伤害守恒、局部强化隔离、延迟快照、NPC 来源、分支继续成长、有限弹道、装备恢复、纯索敌、稳定卡池、付费校验及快照校验；既有世界、城堡、天使、UI 和移动端卡片检查继续执行。离线 DOM 与 Canvas 检查不能替代真实浏览器和触屏试玩。
